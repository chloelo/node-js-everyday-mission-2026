## **題目**

> 健身房系統要新增一張「課程」資料表 `courses`，用來記錄開課資訊。PM 提出的欄位需求如下：
>
> - `id`：主鍵，自動遞增
> - `title`：課程名稱，最多 50 字，必填
> - `code`：課程代碼，最多 20 字，必填且不可重複（例如 `YOGA-001`）
> - `capacity`：課程人數上限，整數，必填
> - `description`：課程介紹，可以留空
> - 需要記錄「這筆課程資料是什麼時候建立的」與「最後一次是什麼時候被修改的」，且不希望工程師每次寫入/修改資料時要自己手動填這兩個欄位

請根據以上需求，回答下列問題：

1. 上面列出的欄位裡，哪些需要設定成「必填」？哪些需要設定成「唯一」？哪個欄位該當主鍵？請逐一說明。
2. `code` 欄位除了要「必填」，還需要哪個額外設定？為什麼這個需求不能只靠「必填」就滿足？
3. 「建立時間」與「更新時間」這兩個欄位，在 entity 裡通常會怎麼設定，才能不用工程師自己手動塞值？
4. 如果 `capacity` 一開始被設計成 `varchar` 型別，短期內畫面顯示可能看不出問題，但之後可能會在什麼情境下才發現選錯型別？

## 回答

### 1.

`title`、`code`、`capacity` 需要設定為必填，也就是 `nullable: false`。

`code` 需要設定為唯一，也就是 `unique: true`，因為課程代碼不能重複。

`id` 是主鍵，並設定 `generated: true` 讓它自動遞增。

### 2.

`code` 除了必填之外，還需要設定 `unique: true`。

因為 `nullable: false` 只能保證 `code` 有值，不能保證不同課程的 `code` 不會重複。

例如兩筆資料都可以有 `code = 'YOGA-001'`，所以還需要 `unique: true`。

### 3.

可以使用 `createDate: true` 和 `updateDate: true`。

`createdAt`：

    {
      type: 'timestamp',
      createDate: true,
    }

`updatedAt`：

    {
      type: 'timestamp',
      updateDate: true,
    }

這樣新增資料時會自動記錄建立時間，更新資料時會自動更新修改時間，不需要工程師自己填。

### 4.

如果之後需要拿 `capacity` 做排序、篩選或運算，就會發現 `varchar` 不適合。

例如要找 `capacity > 20`、按照人數排序，或把多堂課的人數加總時，字串的比較和數字不同，例如 `"9"` 可能會排在 `"10"` 後面。

所以 `capacity` 應該使用整數型別。
